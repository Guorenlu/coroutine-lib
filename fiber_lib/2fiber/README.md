# 协程模块（fiber）简介

## 从哪里开始，需要什么类？

建议从 `fiber`（协程）模块入手，理解协程的基本实现和运行机制。随后可以逐步了解 `thread`（线程）、`scheduler`（调度器）、`ioscheduler`（IO调度器）、`timer`（定时器）、`hook`（HOOK系统调用）等模块。

### 主要涉及的核心类
- **thread**：线程封装与同步，配合协程实现多核并发。
- **fiber**：协程的创建、切换、暂停与恢复，是任务实际运行的单元。
- **scheduler**：调度器，自动管理和调度协程的执行顺序。
- **ioscheduler**：IO调度器，结合 epoll 实现 IO 事件驱动的协程调度。
- **timer**：定时器，支持定时任务的创建、删除和触发。
- **hook**：HOOK模块，重定义系统调用（如 sleep、read、write），实现协程级别的挂起和恢复。

---

## 主要内容与模块说明

### thread
- **作用**：解决协程只能利用单核 CPU 的缺点，通过多线程+多协程更好地利用多核资源。
- **说明**：线程池、线程同步等，通常为调度器和 IO 调度器提供线程支持。

### fiber
- **作用**：协程的核心，负责协程的创建、切换、挂起和恢复，所有任务代码都运行在 fiber 中。
- **说明**：每个 fiber 拥有独立的栈和上下文，支持高效的用户态切换。

### scheduler
- **作用**：自动调度 fiber 的执行顺序，实现协程的挂起和恢复。
- **说明**：如果没有 scheduler，用户需要手动管理协程的切换，灵活性和智能性不足。

### ioscheduler
- **作用**：在 scheduler 基础上扩展，支持 IO 事件驱动的协程调度。
- **说明**：通过 epoll 监听 fd 上的读写事件，事件触发后将对应 fiber 放入调度器队列。

### timer
- **作用**：为服务器提供定时任务支持。
- **说明**：使用最小堆管理定时器，支持定时任务的创建、删除和取消。超时后通过信号触发 epoll 唤醒调度。

### hook
- **作用**：HOOK 系统调用，使其与协程框架更好配合，实现真正的非阻塞。
- **说明**：如 sleep(1) 不再阻塞线程，而是将任务挂起，作为定时任务放入 timer，超时后唤醒 epoll，再由调度器恢复执行。

---

## 模块之间的协作关系

- **fiber** 是任务的执行单元，所有业务代码都运行在 fiber 中。
- **scheduler** 负责管理 fiber 的调度，实现协程的挂起与恢复。
- **ioscheduler** 在 scheduler 基础上扩展，支持 IO 事件驱动的 fiber 调度。
- **timer** 为 scheduler 和 ioscheduler 提供定时任务支持，实现定时唤醒。
- **hook** 改变系统调用行为，使 sleep、read、write 等操作能与协程框架协同，实现真正的异步非阻塞。

---

## 推荐阅读顺序

1. **fiber**：理解协程的基本实现和切换机制。
2. **thread**：了解线程池和线程同步，为多核并发做准备。
3. **scheduler**：学习协程的自动调度。
4. **ioscheduler**：掌握 IO 事件驱动的协程调度。
5. **timer**：理解定时任务的实现和管理。
6. **hook**：掌握如何将同步系统调用转为协程友好的异步操作。

---

## 总结

本协程库通过 fiber、scheduler、ioscheduler、timer、hook 等模块协作，实现了高效的用户态协程调度、IO 事件驱动和定时任务管理，是构建高性能服务器的基础。
